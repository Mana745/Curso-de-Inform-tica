Mostra produtos e informações de forma organizada.

🛒 Vitrine de e-commerce

Além de apresentar produtos, prepara caminhos claros para interesse, contato ou compra.

Vitrine não é o mesmo que sistema completo de comércio eletrônico

Pagamento, estoque, autenticação, pedidos persistentes, dados de clientes e entrega exigem componentes adicionais. Nosso projeto final é o front-end da vitrine.

4. O que uma vitrine precisa deixar claro?

Quem vende?

Nome do negócio, associação, feira ou produtor responsável.

O que vende?

Produtos bem identificados.

Como é?

Foto e descrição verdadeira.

Quanto custa?

Preço real e atualizado, se for exibido.

Como comprar?

Canal oficial de contato ou sistema de pedido.

Onde atende?

Região de entrega/retirada sem expor endereço residencial desnecessariamente.

❌ Para evitar

R$ 10,00

Colocar preço inventado apenas para “parecer loja”.

Usar preço fornecido pelo responsável e mantê-lo atualizado, ou escrever “Consulte o valor” quando a atividade não tiver dados reais.

9. O que significa responsivo?

Design responsivo é construir a página para que ela se adapte a diferentes tamanhos de tela e continue utilizável.

Não criamos “um site para PC” e outro “para celular”

Podemos usar a mesma estrutura e deixar o CSS reorganizar o conteúdo conforme o espaço disponível.

10. A meta viewport

Confira se o <head> contém:

<meta name="viewport" content="width=device-width, initial-scale=1">

Isso ajuda o navegador móvel a usar a largura do dispositivo como referência para o layout.

11. Imagens que não estouram a tela

img { max-width: 100%; height: auto; }

Assim a imagem pode diminuir quando o espaço disponível for menor, mantendo sua proporção.

12. Grade flexível dos produtos

.catalogo { display: grid; grid-template-columns: repeat(auto-fit, minmax(220px, 1fr)); gap: 20px; }

O navegador encaixa quantas colunas couberem, respeitando o tamanho mínimo definido para os cards.

13. Uma media query simples

@media (max-width: 600px) { body { padding: 10px; } .topo h1 { font-size: 1.8rem; } .produto { padding: 14px; } }

Uma media query permite aplicar estilos conforme características da tela/viewport.

Não é “detectar marca de celular”

Estamos reagindo ao espaço disponível, não criando regras para um modelo específico de aparelho.

14. Botões precisam funcionar com toque

button, .botao-contato { padding: 12px 16px; font-size: 1rem; }

Alvos muito pequenos são ruins no celular. Os controles precisam ser fáceis de tocar e ler.

15. Animação também deve respeitar o usuário

Se o projeto tiver efeitos, mantenha-os discretos. Uma melhoria opcional é respeitar quem prefere menos movimento:

@media (prefers-reduced-motion: reduce) { * { scroll-behavior: auto; transition: none; } }

É uma introdução à ideia de acessibilidade: nem todo usuário interage com a página da mesma maneira.

17. Teste 2 — simular celular no PC

Antes mesmo de usar um telefone:

1. Deixe o navegador em modo janela. 2. Arraste a lateral para diminuir a largura. 3. Observe os cards. 4. Confira se o texto continua legível. 5. Confira se nada sai da tela.

Esse teste já encontra muitos problemas

Se os cards se reorganizam em menos colunas conforme a janela diminui, a grade está reagindo ao espaço disponível.

19. Vendas reais: qual será o próximo passo?

Escolha um canal oficial do negócio

Uma vitrine real pode direcionar o interessado para um número comercial, e-mail institucional, formulário ou outro canal autorizado pelo responsável pelo negócio.

Não use dados pessoais do aluno como contato comercial

Telefone, endereço e conta pessoal de criança/adolescente não devem virar contato público da loja. Se o projeto representar um negócio real, o responsável adulto ou a instituição define o canal oficial.

20. E um formulário de pedido?

HTML possui formulários para coletar informações, mas coletar e enviar dados de pessoas exige mais cuidado.

<form> ... </form>

Não vamos coletar dados reais nesta aula

Um formulário de produção precisa ter destino para os dados, validação, segurança, política de privacidade e tratamento responsável das informações. Isso está além do escopo deste curso básico.

21. E pagamento?

Não crie campo de cartão “de mentira”

Uma página HTML estática não deve pedir número de cartão, senha bancária ou outros dados financeiros. Pagamentos reais devem usar infraestrutura apropriada e segura escolhida pelo responsável pelo negócio.
