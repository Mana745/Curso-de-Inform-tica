Criando um Catálogo de Produtos Regionais

3. Primeiro: o que é um catálogo?

Um catálogo organiza produtos ou serviços para que uma pessoa consiga comparar opções e encontrar informações importantes.

Nome

O que é o produto?

Imagem

Como ele é visualmente?

Descrição

O que precisamos saber?

Ação

O que o usuário pode fazer?

4. Nossa feira digital terá 12 produtos

Os produtos devem representar a realidade da região da turma. Exemplos possíveis:

🍌 Frutas

Banana, açaí, cupuaçu, manga ou outras realmente presentes na região.

🌾 Farinhas

Farinha de mandioca e outros produtos locais.

🍬 Doces

Doces e preparações regionais.

🧀 Produção artesanal

Queijos ou outros produtos quando fizerem sentido para a comunidade.

Não é obrigatório usar exatamente esses produtos

A turma deve escolher itens que façam sentido para sua cidade ou comunidade. O catálogo é regional, não uma lista inventada pelo computador.

5. Um produto pode ser um <article>

O elemento <article> representa um conteúdo independente dentro de uma página. Um card de produto é um exemplo possível desse tipo de conteúdo.

<article class="produto"> ... </article>

6. Estrutura de um card

<article class="produto"> <img src="imagens/banana.jpg" alt="Cacho de bananas"> <h2>Banana</h2> <p>Produto disponível na feira local.</p> <button type="button">Confirmar Pedido</button> </article>

7. O botão <button>

<button> é um elemento interativo que pode ser ativado com mouse, teclado, toque ou outras tecnologias de interação.

<button type="button">Confirmar Pedido</button>

O botão sozinho não faz um pedido real

HTML cria o botão, mas para registrar pedidos de verdade seria necessário adicionar lógica — por exemplo JavaScript e, em muitos casos, um sistema no servidor. Nesta aula o botão será apenas uma simulação local de interação.

8. Por que usar type="button"?

<button type="button">Confirmar Pedido</button>

Como nosso botão não está enviando um formulário real, usamos type="button" para deixar clara sua função simples.

9. Fazendo o botão responder ao clique

Para o aluno perceber a interação, usaremos uma pequena instrução JavaScript já pronta:

<button type="button" onclick="confirmarPedido('Banana', this)" > Confirmar Pedido </button>

O aluno não precisa dominar JavaScript hoje. A função será fornecida pronta e apenas demonstrará que o clique aconteceu.

10. A função pronta

<script> function confirmarPedido(produto, botao) { botao.textContent = "Pedido selecionado ✓"; alert(produto + " foi selecionado nesta demonstração."); } </script>

Simulação, não comércio eletrônico

Nenhuma informação é enviada para loja, produtor, banco ou servidor. Ao atualizar ou fechar a página, a demonstração pode desaparecer.

12. Repetição com organização

Os 12 produtos terão praticamente a mesma estrutura:

<article class="produto"> imagem nome descrição botão </article>

O conteúdo muda, mas a estrutura permanece consistente.

Isso já é pensamento de desenvolvimento

Quando reconhecemos um padrão repetido, conseguimos organizar o código e reduzir confusão.

13. Criando uma área para todos os produtos

<section class="catalogo"> <article class="produto">...</article> <article class="produto">...</article> <article class="produto">...</article> </section>

14. CSS para organizar em colunas

.catalogo { display: grid; grid-template-columns: repeat(auto-fit, minmax(220px, 1fr)); gap: 20px; }

Essa regra cria uma grade que consegue reorganizar os cards conforme o espaço disponível.

15. CSS para cada produto

.produto { background-color: white; color: #222; padding: 16px; border-radius: 14px; box-shadow: 0 6px 16px rgba(0,0,0,0.15); } .produto img { width: 100%; border-radius: 10px; }

16. Estilizando o botão

button { background-color: darkgreen; color: white; border: none; padding: 10px 14px; border-radius: 8px; cursor: pointer; }

O botão continua sendo um elemento HTML interativo; o CSS apenas muda sua aparência.

17. Um catálogo precisa de informações verdadeiras

Não invente preço, origem ou qualidade

Se a atividade usar produtos reais, coloque somente informações fornecidas pelo professor, produtor ou pesquisa confiável. Para fins de aula, também podemos simplesmente omitir preços.
