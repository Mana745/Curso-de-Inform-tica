O Pensamento dos Computadores

Antes de criar uma página da internet, precisamos aprender uma ideia que aparece em toda programação: resolver um problema usando passos claros e organizados.

Desafio da aula: escrever um algoritmo tão claro para ligar o computador e abrir o navegador que outra pessoa consiga seguir sem precisar adivinhar o que você quis dizer.

3. O que é lógica?

Nesta aula, vamos usar a palavra lógica como a capacidade de organizar ideias e regras de maneira coerente para resolver um problema.

Exemplo simples

Se eu quero abrir um site, primeiro preciso ter um computador ligado e um navegador aberto. Não faria sentido tentar digitar o endereço do site antes de abrir o navegador.

4. O que é um algoritmo?

Um algoritmo é uma sequência de instruções criada para realizar uma tarefa ou resolver um problema.

🍰 Receita

Separar ingredientes → misturar → colocar na forma → assar.

🪥 Escovar os dentes

Pegar a escova → colocar creme dental → escovar → enxaguar.

A comparação com receita ajuda, mas algoritmo é mais amplo

Na computação, algoritmos podem incluir decisões, repetições, cálculos e outras regras. Hoje começaremos apenas pela sequência.

5. A ordem importa

✅ Ordem possível

1. Pegue o copo. 2. Abra a torneira. 3. Encha o copo. 4. Feche a torneira.

❌ Ordem problemática

1. Encha o copo. 2. Pegue o copo. 3. Abra a torneira.

O primeiro passo já exige algo que ainda não aconteceu.

6. “O computador obedece de cima para baixo” — com uma correção importante

Para começar, vamos imaginar um programa simples executando instruções em sequência. Muitas instruções são realmente processadas na ordem em que aparecem.

Início
→
Passo 1
→
Passo 2
→
Resultado

Mas programas reais não são sempre uma linha reta

Mais tarde você verá decisões, repetições, eventos e tarefas que podem mudar o fluxo. Nesta primeira aula, usamos a sequência simples para aprender o fundamento.

7. O computador não completa aquilo que você “quis dizer”

Quando programamos, precisamos dar instruções compatíveis com a linguagem e com o que o sistema consegue executar.

❌ Humano entende, computador não necessariamente

Abre aí a internet.

✅ Passos observáveis

1. Ligue o computador. 2. Aguarde o sistema iniciar. 3. Abra o navegador. 4. Clique na barra de endereço. 5. Digite o endereço desejado. 6. Pressione Enter.

8. O segredo: não pular etapas importantes

Um algoritmo precisa ser claro para quem vai executá-lo.

Exemplo: “Faça um sanduíche”

Isso descreve o objetivo, mas não explica como chegar até ele.

Exemplo melhor
1. Separe duas fatias de pão. 2. Coloque o recheio em uma delas. 3. Coloque a segunda fatia sobre o recheio.

9. Mas não precisamos escrever cada movimento do corpo

Detalhe suficiente, não detalhe infinito

“Mova o braço 14 centímetros” normalmente seria exagero para uma receita. A boa instrução tem detalhes suficientes para a pessoa ou máquina entender a tarefa no nível necessário.

Esse equilíbrio será muito importante quando começarmos a escrever código.

10. Atividade principal — Algoritmo para ligar o PC e abrir o navegador

Primeiro, faça no papel. Não copie o exemplo pronto.

Comece com o computador desligado.
Qual é a primeira ação necessária?
Continue até o sistema estar pronto.
Há algum momento em que precisamos aguardar?
Abra o navegador.
Como outra pessoa identifica onde clicar?
Chegue até um site.
Onde o endereço é digitado? Como confirmar?

11. Modelo para preencher no papel

OBJETIVO: Ligar o computador e abrir um site. PASSO 1: ______________________________________ PASSO 2: ______________________________________ PASSO 3: ______________________________________ PASSO 4: ______________________________________ PASSO 5: ______________________________________ PASSO 6: ______________________________________ PASSO 7: ______________________________________ RESULTADO ESPERADO: _______________________________________________

12. Agora vem a parte mais importante: testar

Troque o papel com um colega.
Ele deve seguir exatamente a sequência escrita.
Não explique oralmente.
Se ele precisar perguntar, talvez falte clareza.
Marque onde houve dúvida.
Esse é um possível defeito no algoritmo.
Corrija e teste novamente.
Melhorar instruções faz parte do trabalho.

13. Encontrou um erro? Isso é bom

🐞 Primeiro contato com a ideia de “bug”

Se a sequência produz um resultado diferente do esperado, existe algo para investigar. Programadores passam muito tempo testando, encontrando problemas e corrigindo instruções.

Errar durante o teste não significa fracasso. Significa que o teste revelou uma informação útil.
